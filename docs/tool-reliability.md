# Bounded Telegram tools

The existing Telegram scope remains `skills`, `clarify`, `todo`, `session_search`, `mcp-aqla` and `mcp-sheets`. File, shell, code execution and delegation tools remain unavailable. A fixed turn note points time questions to local source lookup and explains reachable output recovery; it changes no authorization rule or Master skill.

Large native results in a registered Aqla profile receive an opaque `output_id`. Call `aqla_read_tool_result(output_id, offset=0, limit=4096)` and follow `next_offset` until `eof`. Offsets count characters. Pages preserve Unicode, escaped text and long lines, including text resembling an untrusted-result delimiter. The byte limit includes JSON escaping and native untrusted framing. Strictly bounded reader pages never spill recursively, even under a lower aggregate budget.

Receipts bind the native profile home, actual conversation session, immutable output generation, content hash and expiry. Reused call IDs receive new generations. Ownership survives subsequent turns and restart/resume; another session or profile cannot use the reference. Links, hard links, changed storage and altered/expired receipts are rejected. Transcript filenames and caller-supplied session IDs confer no access. Expired generations receive periodic targeted cleanup. Contents remain untrusted data. When persistence fails, inspect durable status/diagnostics; never repeat an effectful tool merely to recover its response.

Singleton miswrapped calls to enabled read/catalog/interaction core tools follow the same native dispatch as direct calls, retaining their call ID; this includes safe catalog singletons through `tool_describe` or `tool_search`. Multi-entry calls, recursive `tool_call` execution bridges, unavailable tools, mutation payloads and malformed arguments retain native rejection semantics. Nullable enum/constant validation preserves constraints and local definitions while accepting documented null values. The monthly diagnostic flag accepts booleans or exact strings `true`/`false`; invalid/null values are rejected before publication-capable hooks.

`source_lookup(start, end, ...)` reads local retained state only. Use aware timestamps, for example `2026-10-11T17:39:00+02:00` through `2026-10-11T17:40:00+02:00`; the end is exclusive. `time_field` selects original `sent_at` or `received_at`. Berlin timestamps retain explicit DST offsets. Optional source names/IDs, symbol, account and network filters preserve distinct bindings. `status` matches an event status or bound trade status. Event status `executed` alone is not fill proof. Results show confirmed own entry-fill counts/quantities separately from unresolved operations. They never join sources, reconcile an exchange, interpret, acknowledge or change a trade.

Follow `next_cursor` with the same interval/filters and `offset=0`. Cursors bind matching retained projections; unrelated arrivals do not invalidate pages. Changed matching data or filters requires restarting at offset zero. Missing/pruned original revisions remain explicit, with saved diagnostics and unknown time-window membership. Never infer their source time from plan creation time. Retained completeness does not establish historical completeness or prove an absent message was never received.

`status`, `source_context`, `trade_diagnostics` and `journal_read` retain complete defaults with `view="full"`. Explicit `view="compact"` provides byte-bounded model pages and full-detail links. These are live views: continued pages require returned `view_version`. If the version changes, retrieve a full view and follow its immutable native receipt. Journal compact paging uses `view_offset`/`view_limit`; ordinary offsets, scan cursors, fingerprints and acknowledgement contracts remain unchanged. A compacted journal body never claims `_verified=true`; full-record fingerprint verification is labelled separately.

Symbol diagnostics report candidate totals and continuation beyond twenty trades. Source attribution retains `sources` and adds plan-bound originals, missing revisions, proven later edits and retained edits whose relationship to a missing original is unknown. Internal source processing retains complete historical reply ancestry.

Private native hook contracts are checked against the pinned runtime before mutation. Install/undo/reinstall remains idempotent. True reload revokes old Setup/turn claims and binds the fresh extension at the trusted live rewire boundary on the gateway event loop. Admission stays locked while no bound extension is available; reconnect and repeated reload retain one admission handler and worker set.
